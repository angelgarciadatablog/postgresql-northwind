# postgresql-northwind

**Northwind** adaptada a PostgreSQL, lista para aprender y enseñar SQL relacional.

Un solo archivo — `seed.sql` — que crea las 12 tablas y carga 830 pedidos con sus 2.155 líneas de detalle. Lo puedes cargar en tu PostgreSQL local, en la nube o en Docker.

---

## 1. Qué es Northwind

La base de datos de ejemplo de **Microsoft** (licencia MIT), que simula una empresa importadora de alimentos: clientes, pedidos, productos, proveedores y empleados. Es el estándar de facto para enseñar SQL desde hace décadas.

Esta versión está **adaptada a PostgreSQL** y corregida para que sirva como material de aprendizaje (ver sección 6).

## 2. Qué contiene

| Tabla | Filas | Qué es |
|---|---:|---|
| `region` | 4 | Regiones comerciales |
| `territories` | 53 | Territorios de venta, cada uno en una región |
| `categories` | 8 | Categorías de producto |
| `suppliers` | 29 | Proveedores |
| `shippers` | 6 | Transportistas |
| `employees` | 9 | Empleados (con jerarquía jefe → subordinado) |
| `employee_territories` | 49 | Qué empleado cubre qué territorio (muchos a muchos) |
| `customers` | 91 | Clientes |
| `products` | 77 | Productos |
| `orders` | 830 | Pedidos |
| `order_details` | 2.155 | Líneas de cada pedido (muchos a muchos con medidas) |

Los pedidos van de **julio de 1996 a mayo de 1998**.

En [`csv/`](csv/) están las mismas tablas en CSV, por si quieres mirar los datos sin instalar nada.

## 4. Cómo cargarla

Elige **una** de las tres. En todas, el resultado es idéntico.

### Opción A — PostgreSQL local

Necesitas PostgreSQL instalado (`psql --version` para comprobarlo).

```bash
git clone https://github.com/angelgarciadatablog/postgresql-northwind.git
cd postgresql-northwind

createdb northwind
psql -d northwind -f seed.sql
```

### Opción B — En la nube (Neon, Supabase, o cualquier PostgreSQL)

No necesitas instalar nada más que el cliente `psql`.

```bash
git clone https://github.com/angelgarciadatablog/postgresql-northwind.git
cd postgresql-northwind

psql "postgresql://usuario:contrasena@host/basededatos?sslmode=require" -f seed.sql
```

La cadena de conexión te la da tu proveedor. En Neon: **tu proyecto → Connect → Connection string**.

> Si no quieres pegar la cadena en la terminal cada vez, copia `.env.example` a `.env`, rellena tus valores y usa `psql "$NEON_DATABASE_URL" -f seed.sql`.

### Opción C — Docker

No necesitas PostgreSQL instalado. Solo Docker.

```bash
git clone https://github.com/angelgarciadatablog/postgresql-northwind.git
cd postgresql-northwind/docker

docker compose up -d
```

Levanta PostgreSQL 17 en el **puerto 5433** con la base ya cargada. Para conectarte:

```bash
psql "postgresql://northwind:northwind@localhost:5433/northwind"
```

Para borrarlo todo y empezar de cero:

```bash
docker compose down -v && docker compose up -d
```

## 5. El botón de reset

`seed.sql` **borra y recrea todo**. Es intencional.

Practicando vas a hacer `DELETE`, `UPDATE` y `DROP TABLE` — de eso se trata. Cuando quieras volver al estado inicial, ejecuta el mismo comando otra vez:

```bash
psql -d northwind -f seed.sql
```

No hay forma de "arruinar" la base de manera permanente.

## 6. Qué se cambió respecto al Northwind original

Este no es un volcado tal cual. Se corrigieron cosas que estorbaban para aprender:

| Cambio | Por qué |
|---|---|
| Precios y fletes en `numeric(10,2)`, no `real` | `real` es coma flotante: `SUM()` devuelve resultados como `1234.5600000000001`. **Nunca uses float para dinero.** |
| `discontinued` es `boolean`, no `0`/`1` | Es lo que PostgreSQL espera |
| Todas las PK numéricas son `GENERATED BY DEFAULT AS IDENTITY` | Puedes hacer `INSERT` sin inventarte el `id` a mano |
| Secuencias sincronizadas con `setval()` | Sin esto, tu primer `INSERT` chocaría con un `id` existente. Es el error clásico al migrar datos con ids fijos |
| Restricciones `CHECK` añadidas | Cantidad > 0, descuento entre 0 y 1, precios y stock ≥ 0, fecha requerida ≥ fecha de pedido, nacimiento < contratación |
| `NOT NULL` en lo que nunca puede faltar | `orders.customer_id`, `orders.order_date`, `products.category_id`, etc. |
| Ids `smallint` → `integer` | `smallint` tope en 32.767 y `order_id` ya va por 11.077 |
| Eliminadas `customer_demographics` y `customer_customer_demo` | Vacías en el original (0 filas), solo añadían ruido |
| Eliminadas las columnas `picture`, `photo`, `photo_path` | Blobs vacíos y URLs de un servidor que no existe desde 1998 |
| Índices sobre las FK más consultadas | Para que los `JOIN` de práctica no vayan lentos |

**Las restricciones son a propósito.** Intenta insertar una cantidad negativa o un cliente que no existe: la base te lo va a rechazar. Eso es exactamente lo que hace un motor relacional y lo que un almacén analítico (BigQuery, por ejemplo) **no** hace.

## 7. Consultas para empezar

```sql
-- ¿Quién le reporta a quién? (self-join)
SELECT  e.first_name || ' ' || e.last_name AS empleado,
        j.first_name || ' ' || j.last_name AS jefe
FROM employees e
LEFT JOIN employees j ON e.reports_to = j.employee_id
ORDER BY j.last_name NULLS FIRST;

-- Ventas totales por categoría
SELECT  c.category_name,
        SUM(od.unit_price * od.quantity * (1 - od.discount)) AS ventas
FROM order_details od
JOIN products   p ON p.product_id  = od.product_id
JOIN categories c ON c.category_id = p.category_id
GROUP BY c.category_name
ORDER BY ventas DESC;

-- Pedidos que aún no se han despachado
SELECT order_id, customer_id, order_date, required_date
FROM orders
WHERE shipped_date IS NULL
ORDER BY required_date;

-- Ranking de clientes por facturación (función de ventana)
SELECT  c.company_name,
        SUM(od.unit_price * od.quantity * (1 - od.discount)) AS total,
        RANK() OVER (ORDER BY SUM(od.unit_price * od.quantity * (1 - od.discount)) DESC) AS puesto
FROM customers c
JOIN orders        o  ON o.customer_id = c.customer_id
JOIN order_details od ON od.order_id   = o.order_id
GROUP BY c.company_name
ORDER BY puesto
LIMIT 10;
```
